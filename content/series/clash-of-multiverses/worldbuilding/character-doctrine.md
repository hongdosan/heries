# 등장인물 문서 작성 원칙 (Character Doctrine) — SSOT

> 본 문서는 작가 전용 (`worldbuilding/`) 영역. 작가 모드 unlock (사이트 `/unlock` 키 입력 또는 `?unlock=KEY`) 시만 노출. H-eries 의 *모든 등장인물 카드 작성·갱신* 시 본 문서를 우선 참조.

## 1. 7 핵심 원칙 (작가 결정)

1. **시점 분리** — 독자가 보는 카드와 작가가 보는 카드 내용이 **달라야** 한다.
2. **독자 = 무스포** — 독자 카드에서 스포가 될 수 있는 정보는 일체 배제.
3. **작가 = 백엔드** — 스포 / 향후 방향성 / 미공개 떡밥은 작가만 본다 (`/unlock` 통해 작가 모드 진입).
4. **살아있는 문서** — 한번 정하면 끝 X. 챕터 진행에 따라 항상 업데이트.
5. **카드는 스토리를 *따라간다*** — 스토리가 카드를 따라가는 게 아니다. 카드 = 스토리 *후처리*.
6. **본문 우선** — 독자는 카드를 읽고 인물을 알아가는 게 아니라, 본문을 읽고 카드에서 *확인* 한다.
7. **"왜" 의 기록 의무** — 글만 있는 매체. 모든 인물 행동·변화에 *왜* 가 명시돼야 한다.

## 2. 운영 메커니즘

### 2-1. 라이프사이클 — 언제 / 누가 갱신

- **트리거** = 챕터 발행 시. 그 챕터에 등장하거나 변화가 있는 모든 인물 카드 갱신 의무
- **갱신자** = 작가 (사용자). 본문 작성 후 동일 사이클에 카드 갱신
- **자동 게이트** = `heries-continuity-reviewer` 가 챕터 작성 후 자동 호출 → 카드 미갱신 발견 시 보고
- **챕터 발행 ↔ 카드 갱신** 의 분리 금지. 본문만 발행하고 카드 stale 두면 정책 위반

### 2-2. 독자 카드 = *현재 발행 시점 snapshot*

- 독자 절은 **"마지막 발행 챕터까지 노출된 사실"** 만 포함
- frontmatter `reader_snapshot: ep-NN` 필드 = 어느 챕터까지 정보인지 명시
- 그 다음 챕터에서 밝혀질 사실은 *작가 절* 에만

### 2-3. 신규 인물 = 본문 먼저, 카드 나중

- 본문 첫 등장 *이전* 에 독자 카드 생성 금지 (mob-pool 에만 가둠)
- 첫 등장 챕터 발행 *후* 단독 카드 생성. `first_appearance: ep-NN`
- 작가 카드 (작가 백엔드용) 는 *언제든* 미리 작성 가능

### 2-4. "왜" 의 본문 ↔ 카드 동시 기록

- 독자 카드의 모든 사실에 *근거 한 줄* 동반: `(ep-03 작전 후 의무대 대화에서 밝혀짐)`
- 본문에서 *왜* 가 풀이되지 않은 정보는 독자 카드에 못 들어옴 (스포)
- 작가 절은 *왜* 의 백엔드 = 본문에서 *언젠가* 풀이될 인과까지 기록

### 2-5. 변경 이력 절

- 작가 절 안 `## 갱신 이력` 절 (마스킹 영역)
- 한 줄 형식: `ep-NN (YYYY-MM-DD): 무엇이 어떻게 갱신됐는지 + 왜`
- 독자 절 변경은 *본문 챕터 발행과 함께* 만. 임의 변경 금지

### 2-6. 단역 ↔ 단독 카드 승격 임계

- 첫 등장 시 = `4-minor/_mob-pool.md` 에 1~2 줄
- *이름 + 대사 + 인과* 가 있는 등장, 또는 *2 챕터 이상 누적* = 단독 카드 승격 자격
- 승격 결정 = 작가 자유. 자동 X

### 2-7. 권속화된 인물의 특수 처리

- *원본 인물 카드* 그대로 (생전 정보 = 독자 절)
- 권속 상태 · 복종도 · 우진혁과의 관계 = 작가 절에만
- 권속화 *사건* 자체는 본문에서 공개되는 시점부터 독자 절에 포함 가능

## 3. 독자 접근성 (UI 정합)

원칙 #6 (본문 우선) 의 강제 메커니즘:

- **라이브 기본 화면**: 등장인물 탭 = 이름 + 간단 소개글 (`summary`) 카드. 클릭 X
- **예외 = 주인공 (`1-protagonist`)** 만 카드 클릭 → 상세 페이지. 독자가 *왜 이 주인공이 이런 자인지* 이해할 첫 입구
- **작가 모드 unlock** = 모든 인물 상세 페이지 접근 가능 + 마스킹 해제

| 폴더 | 독자 모드 카드 | 작가 모드 |
|---|---|---|
| `1-protagonist/` | 이름 + summary, **클릭 가능 (Link)** | 모든 절 노출 |
| `2-major-supporting/` | 이름 + summary, 클릭 X | 모든 절 노출 |
| `3-antagonist/` | (등장인물 탭에서 *숨김*) | 노출 |
| `4-minor/` | 이름 + summary, 클릭 X | 모든 절 노출 |

## 4. 카드 frontmatter (강제 필드)

```yaml
slug: woo-jin-hyeok
name: 우진혁
origin: original
role: protagonist
first_appearance: tba              # 본문 첫 등장 챕터 (mob-pool 졸업 시점)
reader_snapshot: tba               # 독자 절이 어느 챕터까지의 정보인지 (작가 검증용)
heries_arc: tba                    # 본 작품 소환 시점 (작가 마스킹)
aliases: []
summary: 한 줄 요약                 # 등장인물 탭 카드 + 상세 페이지 hero
```

## 5. 카드 본문 절 구조 (강제)

### 5-1. 독자 절 (마스킹 외 영역, 단일 빌드 dist 안 평문이지만 기본 화면 노출)

```
## 핵심 정체성     # 한 단락. 본문에서 노출된 사실만
## 능력            # 본문에서 공개된 능력만. 미공개 능력은 작가 절
## 외형            # 본문에서 묘사된 외형
## 인간관계        # 본문에서 노출된 관계
## 출신 배경       # 본문에서 풀이된 만큼만
```

각 절에 들어가는 모든 사실 = *본문 출처 한 줄* 동반.

### 5-2. 작가 절 (`## H-eries 분기 — ...` 이하, 작가 모드 unlock 시만 노출)

```
## H-eries 분기 — {작품명} 변형
   - 미공개 떡밥
   - 향후 방향성
   - 권속화 상태 (해당 시)
   - 작가가 결정한 인과 백엔드

## 갱신 이력         # 한 줄 bullet 누적
```

## 6. 강제 검증 게이트

| 게이트 | 위치 | 통과 기준 |
|---|---|---|
| 시크릿 누수 | `scripts/check-secrets.mjs` | dist + commit 내 API 키 / 토큰 / 비밀번호 패턴 0 |
| 작가 모드 마스킹 | runtime (`spoiler.ts`) | sessionStorage `heries:author` 없으면 `## H-eries 분기` / `heries_arc` / 작가 라우트 마스킹 |
| 카드 ↔ 본문 정합 | `heries-continuity-reviewer` (수동/자동) | 독자 절 사실의 본문 출처 모두 존재 |
| `reader_snapshot` 정합 | 챕터 발행 시 검증 | 발행 챕터 ≥ snapshot, 단 snapshot 가 발행보다 앞서면 = 스포 누수 |
| 신규 인물 차단 | `heries-continuity-reviewer` | 본문 첫 등장 이전 단독 카드 생성 차단 |

## 7. 보안 모델 (책임 분리)

| 영역 | 책임 |
|---|---|
| 라이브 사이트 기본 화면 노출 차단 | 작가 (시스템) |
| 라이브 사이트 devtools / sessionStorage 우회 | **독자 자기 책임** — 스포 봐도 자기 손해 |
| GitHub repo clone 후 작가 콘텐츠 열람 | **독자 자기 책임** |
| 일부러 빌드해서 dist 분석 | **독자 자기 책임** |

이 모델은 작가의 *과한 보안 부담을 덜고* 독자의 *능동 우회 책임을 명시*. CLAUDE.md §원칙 #9 정합.
